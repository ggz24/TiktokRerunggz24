# Boxphone Lab 2 — ข้อความแยกเครื่องและฟังต่อเนื่อง

ใช้ Start.cmd ในโฟลเดอร์นี้ เปิด http://127.0.0.1:8766 รุ่นนี้ใช้พอร์ตใหม่เพื่อไม่ชนกับรุ่นเดิมบน 8765 ป้ายชื่อที่เคยบันทึกในเบราว์เซอร์พอร์ตเดิมจะไม่ย้ายมาอัตโนมัติ ใช้ ADB serial ตรวจเครื่องก่อนตั้งเลขใหม่

## ทดสอบข้อความแต่ละเครื่องโดยไม่ใช้ AI

1. เลือกเครื่องด้านซ้าย
2. ส่วน “ข้อความแยกแต่ละเครื่อง” มีช่องข้อความของทุกเครื่องที่เลือก พิมพ์ข้อความต่างกันได้
3. กด “นำข้อความแยกเครื่องเข้าคิว” แล้ว “เริ่มจำลอง”
4. ถ้าข้อความซ้ำ/คล้ายกันใน 10 นาที จะข้ามรายการนั้น ไม่ส่งข้อความเดียววนทุกเครื่อง

## AI ตามบทพูด

ใส่ API key แล้วเลือกเครื่อง กรอกบทพูดเองหรือถอดเสียงจากไฟล์ กด “AI สร้างแยกเครื่อง” เพื่อร่างและตรวจข้อความก่อนเข้าคิว

“สร้างต่อเนื่องจากบทพูด” ตรวจข้อความในช่องบทพูดเป็นระยะ เฉพาะเมื่อข้อความใหม่ต่างจากที่ประมวลผลแล้ว ค่าเริ่มต้น 45 วินาทีและสูงสุด 3 คำถามต่อรอบ ปรับได้ 30–600 วินาที และ 1–8 คำถาม โปรแกรมหมุนเวียนแจกให้เครื่องที่ได้รับข้อความน้อยกว่าก่อน ไม่จำเป็นต้องสร้างครบทุกเครื่องหากไม่มีประเด็นใหม่

“ฟังไมโครโฟนต่อเนื่อง” หรือ “ฟังเสียงแท็บต่อเนื่อง” รับเสียงเป็นไฟล์ย่อย 20 วินาที ถอดเสียงแล้วเก็บบทพูดล่าสุด 4 ช่วง ปุ่มฟังแท็บต้องเลือกแหล่งที่มีเสียงและเปิดแชร์เสียงใน Chrome/Edge ไม่ได้ดึงเสียงจาก Boxphone เอง

มีตัวกรองระดับเสียงเพื่อข้ามช่วงเงียบ (ไม่ใช่ตัวจำแนกคำพูดระดับสมบูรณ์ เพลงหรือเสียงรบกวนอาจผ่านได้) ถ้างานก่อนหน้ายังประมวลผล ระบบข้ามช่วงใหม่เพื่อไม่สะสมงานค้าง ข้อความ AI ในคิวที่ยังไม่ได้ส่งจะถูกยกเลิกเมื่อบทพูดอัปเดต เพื่อลดข้อความที่ล้าบริบท

AI สร้างข้อความเข้าคิว แต่ต้องกดเริ่มคิวครั้งแรกเอง คิวที่เริ่มแล้วจะรอข้อความรอบถัดไปเมื่อเปิด AI ต่อเนื่อง ปุ่มหยุดจะหยุดทั้งคิวและ AI ผล AI ที่กลับมาหลังกดหยุดจะถูกทิ้ง คำสั่งมือถือที่ถูกส่งออกไปก่อนกดหยุดอาจยังจบงาน

## พิมพ์ทดสอบบนมือถือ / ส่งจริง

เปิดโหมดส่งจริงเพื่อให้เห็นส่วนตั้งค่า TikTok ใช้โหมดเดิมของโปรแกรมในการเลือกพิกัดบนหน้าจอ ต้องบันทึก Chat X/Y และ Send X/Y แยกตาม ADB serial ที่ “บันทึกพิกัดให้เครื่องนี้” ตรวจให้เลือกเครื่องเดียวกันกับที่จับภาพ/ตรวจจับพิกัด

ปุ่ม “พิมพ์อย่างเดียว (ไม่กดส่ง)” ข้างช่องข้อความของแต่ละเครื่องใช้ทดสอบข้อความไทยบนมือถือ โดยไม่กดปุ่มส่ง ต้องติดตั้ง ADBKeyBoard อยู่แล้ว และมีช่องพิมพ์ที่เปิดคีย์บอร์ดได้

การส่งจริงใช้พิกัดที่บันทึกกับแต่ละเครื่องและกดส่งครั้งเดียว ไม่มีการส่งซ้ำด้วยปุ่ม Enter โปรแกรมแสดง “กดส่งแล้ว — ยังไม่ยืนยันผลในแชท” เพราะการที่ ADB ทำงานเสร็จไม่พิสูจน์ว่าปลายทางได้รับข้อความ ตรวจหน้าจอจริงประกอบ

เว้นช่วงรวมอย่างน้อย 30 วินาที และเครื่องเดิม 120 วินาที มีตัวล็อกกันคำสั่งซ้อนทั้งระบบ ตรวจข้อความคล้ายกันใน 10 นาที และหยุดคิวเมื่อเกิดข้อผิดพลาด ไม่ลองส่งซ้ำอัตโนมัติ ค่าดังกล่าวเป็นขีดจำกัดการทำงานของโปรแกรม ไม่ใช่การรับประกันว่าบัญชีจะไม่ถูกแบน

## ข้อมูลและข้อจำกัด

- โมเดลเดิม: gpt-4o-mini-transcribe และ gpt-4o-mini ผ่าน Responses API ใช้ structured JSON output
- API key ไม่ถูกบันทึกลงไฟล์/เบราว์เซอร์ ปุ่มล้างคีย์หยุดงานต่อเนื่องด้วย
- ป้ายชื่อและพิกัดแยกเครื่องเก็บใน localStorage; ข้อความ/คิว/ประวัติ AI อยู่เฉพาะหน่วยความจำของหน้า
- เปิดใช้งานเพียงหน้าต่างเดียว การเว้นช่วงที่ฝั่งเซิร์ฟเวอร์อยู่ในหน่วยความจำและรีเซ็ตเมื่อปิดบริการ
- ไฟล์เพิ่ม: continuous.mjs (ฟัง/สร้าง/แจกข้อความ), message-policy.mjs (กรองซ้ำและเว้นช่วง)
- ไม่ติดตั้ง APK หรือเปิดห้องไลฟ์ให้อัตโนมัติ

## ผลตรวจรุ่นนี้

ตรวจพบอุปกรณ์จริง 20 เครื่องในรอบทดสอบนี้ ทดสอบ UI ด้วยข้อความต่างกันสองเครื่องในโหมดจำลองสำเร็จ

ทดสอบอัตโนมัติ: `node --test message-policy.test.mjs continuous.test.mjs`
ครอบคลุมข้อความคล้าย/ซ้ำ การแจกข้อความ การเว้นช่วง ผล AI ที่มาหลังหยุด และบทพูดเปลี่ยนขณะรอ AI โดยใช้ผล AI จำลอง

ยังไม่ได้ทดสอบ API ที่มีค่าใช้จ่าย การรับเสียงจริง หรือการส่งเข้า TikTok จริงในรอบพัฒนานี้ ต้องให้ผู้ใช้ใส่ API key เลือกแหล่งเสียง และตรวจพิกัดก่อนใช้งานจริง

เอกสาร API ที่ใช้ตรวจรูปแบบ: https://developers.openai.com/api/docs/guides/structured-outputs
