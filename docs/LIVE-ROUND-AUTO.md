# สินค้าและคลิปในแต่ละรอบ LIVE

## ตั้งค่า

1. เปิดบัญชีไลฟ์ → ตั้งค่าไลฟ์ → โหมด AUTO → สินค้าและคลิปในแต่ละรอบ
2. เลือกชุดสินค้าเดิมได้ทั้งชุดของบัญชีนี้และชุดที่ยังไม่ผูกบัญชี หรือสร้างชุดในหน้า Products จาก cURL เพิ่มสินค้า ระบบตรวจว่า session ของคำขอตรงกับบัญชีที่จะไลฟ์ก่อนบันทึกและส่งสินค้า
3. เพิ่มชุดสินค้าและคลิปจากคลังเข้ารายการต่อรอบ เพิ่มรายการเดิมซ้ำได้ เลื่อนด้วย ▲/▼ และลบด้วย ×
4. เปิดเพิ่มสินค้าอัตโนมัติตามต้องการ และบันทึกโหมด AUTO
5. ตั้งเวลาออกอากาศ/พักสำหรับการขึ้นไลฟ์รอบต่อไปอัตโนมัติ หรือกดเริ่มไลฟ์เอง

รายการแต่ละประเภทวนแยกกัน เช่น วิดีโอ A → B → A ส่วนชุดสินค้า 1 → 2 → 3 → 1 เมื่อจำนวนรายการไม่เท่ากัน ระบบใช้หมายเลขรอบเดียวกันแล้ววนตามความยาวของแต่ละรายการ

## การปักหมุด

ไม่ต้องบันทึก cURL ปักหมุดเพิ่ม เปิด “ปักหมุดสินค้าที่เลือก” แล้วเลือกสินค้าในแต่ละชุดต่อรอบ บันทึกโหมด AUTO ระบบใช้ session ของบัญชีและข้อมูล Shop ที่บันทึกกับชุดสินค้า หากไม่เปลี่ยนตัวเลือกจะใช้สินค้าตัวแรก ตัวเลือกเก็บแยกตามชุดและบัญชีใน PostgreSQL

ปักด้วยตนเอง: บัญชีไลฟ์ → เพิ่มสินค้า → เลือกสินค้า → “ปักหมุดตอนนี้” ต้องเริ่ม LIVE ของบัญชีนี้และมีสินค้านั้นในตะกร้าอยู่ก่อน ระบบรับเฉพาะสินค้าที่อยู่ในชุดของเจ้าของบัญชี และใช้ห้องปัจจุบันที่เซิร์ฟเวอร์ตรวจเอง

เมื่อเริ่มห้องใหม่ ระบบส่งเพิ่มชุดสินค้า ก่อนเริ่มวิดีโอ และส่งปักหมุดสินค้าที่เลือกประมาณ 5 วินาทีหลังเริ่มวิดีโอ หากเพิ่มสินค้าไม่สำเร็จ ระบบไม่ส่งปักหมุดตาม ระบบตรวจว่าห้องยังเป็นห้องเดิมและวิดีโอยังส่งอยู่ก่อนปักหมุด

**ที่มาคำสั่ง:** ตรวจ frontend ของ TikTok Shop Creator วันที่ 2026-10-07: `PinLiveProduct` ส่ง POST `/api/v1/streamer_desktop/live_product/pin` มี `room_id`, `product_id` เป็น string และ `op: 1` สำหรับ Pin (`op: 2` คือ Unpin) จาก asset [main.b8c4a585.js](https://sf16-website.neutral.ttwstatic.com/obj/tiktok_web_static/i18n/ecom/alliance/creator/static/js/main.b8c4a585.js) ระบบสร้างคำสั่งนี้โดยไม่ใช้ template Pin ที่ผู้ใช้ต้องวางเอง การตรวจ source ยืนยันรูปแบบคำสั่ง แต่ยังต้องตรวจผลใน LIVE จริงเพื่อยืนยันว่าการส่งจากเซิร์ฟเวอร์และ session ปัจจุบันได้รับการยอมรับ

คำขอเพิ่มสินค้าในรอบใหม่เปลี่ยน `room_id`; Pin สร้าง body ใหม่สำหรับสินค้าและห้องปัจจุบัน ระบบตัด signature จาก URL เก่าที่อาจผูกกับ body เดิม การยอมรับคำขอจากเซิร์ฟเวอร์ต้องทดสอบใน LIVE จริง หาก TikTok ต้องการ signature ใหม่ จะต้องเพิ่มตัวสร้าง signature ที่ตรงกับคำขอ Shop; ห้ามอ้างว่าผ่านเพียงเพราะทดสอบกับ sender จำลองผ่าน

ผล `accepted` หมายถึง API TikTok ตอบรับ ไม่ใช่หลักฐานยืนยันว่าผู้ชมเห็นตะกร้าหรือหมุดแล้ว ผล `rejected`/`unverified` จะแสดงข้อผิดพลาด โดยไม่สร้างห้องใหม่ซ้ำเพียงเพื่อพยายามเพิ่มสินค้า

## ความต่อเนื่องของรอบ

- นับรอบเมื่อสร้างห้องและเริ่มตัวส่งวิดีโอสำเร็จ หากสร้างห้องล้มเหลวจะไม่ข้ามรายการ
- การกู้คืนสตรีมในห้องเดิมใช้คลิปเดิม ไม่เพิ่มหรือปักสินค้าซ้ำและไม่เลื่อนรอบ
- การกู้คืนโดยเปิดห้องใหม่เลื่อนไปรายการถัดไป
- ตัวนับและรายการเก็บใน PostgreSQL รีสตาร์ตระบบแล้วยังคงรอบถัดไป
- แก้รายการสินค้า/วิดีโอแล้วบันทึก จะเริ่มรายการแรกในห้องใหม่ถัดไป ไม่เปลี่ยนคลิปที่กำลังเล่น
- แก้เวลา/ตัวเลือกอย่างเดียวไม่รีเซ็ตลำดับ
- รายการว่างใช้วิดีโอหลักและชุดสินค้าเดิมที่เลือกสำหรับเริ่มไลฟ์
- หากคลิปถูกลบ/ไม่พร้อม ชุดสินค้าถูกลบหรือผูกกับบัญชีอื่น หรือ session ในคำขอไม่ตรงกับบัญชี จะไม่สร้างห้องด้วยรายการนั้น
- กดหยุดระหว่างเตรียมสินค้าจะยกเลิกการส่งวิดีโอและสั่งปิดห้องที่เพิ่งสร้าง

## ไฟล์หลักและการตรวจสอบ

- `apps/api/src/auto-live.ts`: รอบรายบัญชี ตัวนับที่บันทึกถาวร ตารางเวลาและกู้คืน
- `apps/api/src/round-products.ts`: เพิ่มสินค้าและปักหมุดในห้องใหม่
- `apps/api/src/product-pin-store.ts`: คำขอเก่าแบบเข้ารหัสเพื่อความเข้ากันได้ ไม่เป็นเงื่อนไขในการปักหมุด
- `apps/web/components/LiveRoundSettings.tsx`: รายการต่อรอบและตัวเลือกสินค้า Pin
- `apps/web/components/QuickProductSetPanel.tsx`: เลือกสินค้าปักทันที
- `packages/tiktok-client/src/live-product-pin.ts`: สร้างคำขอ Pin โดยใช้ข้อมูล session เดิม

ใช้ชุดทดสอบ API และ tiktok-client ตาม `npm run test -w @live-hub/api` และ `npm run test -w @live-hub/tiktok-client` การทดสอบใช้ข้อมูลจำลองและไม่ส่ง LIVE จริง
